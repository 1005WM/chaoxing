# Android 作业 / 考试读取（本 fork 新增）

更新：2026-11-23。仅 Android 端实现；iOS / macOS 尚未接入。

## 功能

课程详情页在「签到」「看课」之外新增第三个分栏 **作业/考试**，只读展示：

- 该课程下全部作业与考试的名称、服务端原始状态文案、发布日期（作业）或分数（考试）；
- **截止时间精确到时分**（页面提供时），并显示「剩 2 天 3 小时」「已截止」等相对提示；
- 顶部汇总：未完成 / 已完成 / 已过期 / 状态未知的项数，以及「更新于」时间；
- 作业与考试分节展示，各自统计「N 项 · M 项未完成」；
- 下拉刷新与顶栏刷新按钮；加载失败时保留上次结果并提示，重试不会清空已有数据。

课程列表（「我的课程」）也会用到这份数据：

- 每门课右侧显示未完成数量（作业 N / 考试 M），没有未完成项时不显示；
- 列表顶部出现「未完成作业 N 项」入口，点开是**按科目分组**的待办清单；
- 待办条目显示科目名、作业标题、截止时间（精确到分）与状态，点击回到对应课程的「作业/考试」分栏。

**只读**：本功能不打开做题页、不提交、不开始任何作业或考试，也不会修改服务端状态。

## 数据源

官方 App / 移动网页的 H5 列表页，同源 Cookie 鉴权：

```text
GET https://mooc1-api.chaoxing.com/phone/moocAnalysis/workList?courseId={courseId}&classId={classId}
GET https://mooc1-api.chaoxing.com/phone/moocAnalysis/examList?courseId={courseId}&classId={classId}
```

请求失败或返回无法识别的页面时，依次回退到 `mooc1.chaoxing.com` 与 `mooc1-2.chaoxing.com` 的同路径。
`mooc1-api` 是当前客户端常用网关；三套主机共用同一套 Cookie 会话。

### 页面结构

作业（`workList`）：

```html
<dt data="work/phone/task-work?courseId=…&classId=…&workId=…" status="1">
  <h3>第一章 极限（客观题）</h3>
  <p>2026-11-20 发布</p>
  <b>做作业</b>
</dt>
```

- `data`：做题页相对路径，本功能只保存为 `taskUrl`，不自动打开；
- `<h3>`：标题；`<p>`：发布日期；`<b>`：动作/状态文案。

考试（`examList`）：

```html
<tr data="/exam/phone/task-exam?examId=…" title="期中考试" status="2">
  <td>期中考试</td><td>86</td><td>已批阅</td>
</tr>
```

- `title` 属性或第一个 `<td>`：标题；第二个 `<td>`：分数；第三个 `<td>`：状态。

## 截止时间解析

列表页没有统一字段名，时间与文案混在同一行里，因此按「日期时间 + 上下文」提取：

| 场景 | 处理 |
| --- | --- |
| `截止时间：2026-11-27 23:59` | 命中「截止 / 结束 / 到期 / 有效期」关键词的时间优先 |
| `发布时间：2026-11-20 08:30` | 带「发布 / 创建 / 布置」的时间视为发布，排除 |
| `2026-12-01 09:00-11:00` | 区间取结束时间 11:00 |
| `11-27 23:59`（无年份） | 补当前年份；若已过去半年以上则算下一年 |
| 只有日期 `截止日期 2026-11-27` | 时间未知，界面显示「页面未提供时分」，不臆造 23:59 |
| 作业行只有一个无关键词时间 | 视为发布时间，不当作截止（考试允许单个，按考试时间处理） |

截止时间精确到分时，列表按「未完成优先、截止时间升序」排列，汇总卡显示「最近截止」。
当前时间在每次渲染时读取，下拉刷新即可更新相对时间。

## 状态归一化

服务端在不同页面用不同文案表达同一状态，统一归为：

| 统一状态 | 识别文案（包含即命中） | 计入 |
| --- | --- | --- |
| 已批阅 | 已批阅、已评阅、已评分、已出分、已批改、批阅完成 | 已完成 |
| 待批阅 | 待批阅、待评阅、待评分、待批改、批阅中、评阅中 | 已完成 |
| 已过期 | 已过期、过期、已结束、已截止、缺考、未参加 | 已过期 |
| 未完成 | 未完成、未交、未提交、未开始、未做、未作答、未考、做作业、开始考试… | 未完成 |
| 进行中 | 进行中、考试中、作答中、正在 | 未完成 |
| 已提交 | 已交卷、已提交、已交、已作答、已完成、已通过、完成 | 已完成 |
| 状态未知 | 其余文案（如「查看」） | 不计入未完成 |

判定顺序是固定的：先判「已批阅 / 待批阅 / 已过期」，再判带否定前缀的「未完成」类，
然后才是「已交 / 完成」，避免「未完成」被「完成」误命中。界面始终优先显示服务端原文，
所以即使归类为「状态未知」，「是否写完」仍可从原文看出。

## 做题页补全截止时间

列表页常常只给日期（例如 `2026-10-30`），没有时分。对**仍未完成、没有精确截止时间、且带做题页链接**的作业，
会自动以只读方式打开一次它的做题页（`work/phone/task-work`），从页面里找带「截止」关键词的时间：

- 只处理作业，不打开考试页（避免被记录为进入考试）；
- 每门课最多 8 个、最多 3 路并发，失败或找不到就保持列表页原样；
- 只读 GET，不会开始或提交作业；
- 补全结果和列表结果一样会缓存，切回课程不再重复请求。

如果做题页里也只有日期、没有时分，界面会显示「截止 YYYY-MM-DD（页面未提供时分）」而不是编造时间。

## 课程列表总览

`AssessmentOverviewController` 在打开「我的课程」时，用最多 3 路并发把每门课的作业 / 考试读一遍，
按课程 `courseId_classId` 缓存：

- 已缓存的课程不会重复请求，下拉刷新或点刷新按钮才会强制重读；
- 单门课失败只记录该课的错误，不影响其他课程显示；
- 切换账号时取消在途请求并清空缓存，避免串号。

首屏 11 门课约 22 个请求，首次进入会有一定耗时；之后走缓存，只有新课程会补读。

## 页面样本诊断

真实页面结构与预期不符时（解析失败，或状态显示「状态未知」，或有未完成项却拿不到截止时间），
汇总卡会出现「导出页面样本（仅本机）」按钮：

- 把本次请求的作业 / 考试页面片段写到 `下载/DSH-Go/assessment-sample-MMdd-HHmmss.txt`；
- 文件只保存在本机，不会自动上传；内容可能含课程名、作业标题等，分享前请自行打码；
- 在 Issue 或对话里贴出片段即可对照修正解析规则。
